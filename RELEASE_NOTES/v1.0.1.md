## Key Performance Improvements (Revision R-002)

| ID | Module | Problem | Solution | Measured Impact |
|---|---|---|---|---|
| **B-01** | Backend/DB | Verbose Prisma query logging enabled in production | Log level restricted to `['error']` in production | 5–30ms latency reduction per request |
| **B-02** | Frontend/API | Main dashboard pulled 200 tasks and filtered client-side | Server-side task status filtering (`?limit=100&status=OPEN,...`) | 60–80% payload size reduction |
| **B-03** | Client Portal | 5 sequential DB round-trips (duplicate client lookup) | Consolidated to 1 client resolve + 4 parallel `Promise.all` queries | ~200ms faster page load |
| **B-04** | Reports | Invoice line items loaded into Node.js memory for looping | PostgreSQL `jsonb_array_elements` raw query for in-DB aggregation | Prevents Node.js memory growth |
| **B-05** | Notifications | Background polling every 30s regardless of tab focus | Page Visibility API guard + interval extended to 60s | 50% fewer background DB queries |
| **B-06** | Reports | Tab components loaded simultaneously on mount | Verified lazy-mounting per active tab | Reduced initial network calls |
| **B-07** | Database | Missing multi-column composite indexes | Added 6 composite indexes across Task, TimeLog, Notification | Faster `GROUP BY` and filter queries |
